OmniDiff, 코드와 바이너리 콘텐츠를 구분하는 diff 도구

OmniDiff는 파일 유형별 비교를 제공하는 도구다. README는 tree-sitter 기반 구조적 코드 비교와 그림·압축파일·폰트·PDF 등 콘텐츠별 비교, 터미널 UI·배치·JSON 출력을 설명한다. 제작자의 속도·정확도 수치는 독립 재현하지 않았으며 README도 정확도 목표를 아직 충족하지 못했다고 밝힌다.[4]

수집 한계와 읽는 기준

  • 직전 HN 성공 수집 이후의 신규 등록 5건을 선정했다. 최초 발행 또는 출시가 오늘인 5건이라는 뜻은 아니다. 이전 URL·사건 키는 프로그램 대조해 제외한다.
  • 09시 실행은 모델 응답 대기 중 중단되었다. 당일 raw·preview·citation 중간 자료를 재사용했으며 HTML 완성본은 없었다. 원자료 수집 시각은 오전 시각을 유지하고 보고서 기준 시각은 재개 실행 시각으로 기록한다.
  • GeekNews·Product Hunt는 직접 요청과 짧은 재시도 모두 HTTP 403. 실패 출처의 마지막 성공 시각은 전진시키지 않았다. HN·GitHub와 접근 가능한 개별 공개 페이지를 대체 출처로 사용한다.
  • HackerBooks·OmniDiff 최초 공개일은 불명이다. JEPA는 arXiv v1 제출 시각, Frameworks는 원문 datetime, Emitter는 기사 날짜만 확인했다. HN 등록일과 원문 발행일 및 수집일을 구분한다.
  • JEPA는 초록·제출 이력만 확인했다. 증명 본문·코드·동료 심사·실험을 검증하지 않았다. 초록의 성능 수치를 독립 검증 결과로 제시하지 않는다.
  • Emitter는 전문 매체가 업체 설명을 인용한 2차 출처다. 기사 제목의 양산 표현과 본문의 4분기 계획이 병존하며 실출하와 독립 시험을 확인하지 못했다. 시장·비용·성능 배수 주장은 제외한다.
  • 서비스·도구 실행, 추천 품질 평가, 벤치마크 재현, 소자 성능 측정은 하지 않았다. 텍스트만 확인한 화면·시각 품질을 단정하지 않는다. HackerBooks의 JS 카탈로그는 직접 탐색하지 않았다.
  • 외부 링크 검증은 이번 실행에 보존된 HTTP 200 원자료와 HTML href·앵커의 프로그램 대조다. 향후 가용성이나 출처가 주장하는 모든 사실을 보증하지 않는다. 출처 전수 조사도 아니다.
